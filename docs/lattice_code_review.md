## 0. 이게 뭐 하는 거냐 (비유)

내가 차선 따라 가는데 **앞에 장애물**이 있다. 그럼 사람은 이렇게 함:
1. "저기 뭔가 있네" (감지)
2. 왼쪽/오른쪽으로 **살짝 틀어서 갈 여러 방법**을 머릿속에 그림
3. 그중 **부딪히지 않고 제일 자연스러운 길** 선택
4. 그 길로 핸들 틀기

**Lattice planner = 이걸 컴퓨터가 하는 것.** "여러 후보 경로를 그려보고(lattice=격자처럼 뿌림), 안 부딪히는 걸 고른다."

> ⚠️ lattice는 **핸들(횡방향 회피)**만 담당. 속도(브레이크)·정지·신호는 ACC와 behavior가 함.

---

## 1. 큰 그림 (5단계)

```
① 트리거    : 장애물이 내 경로 근처에 있나? 없으면 그냥 직진.
② 후보 생성  : 좌우로 벌어진 경로 6개를 3차곡선으로 그림
③ 충돌 검사  : 각 후보가 장애물이랑 겹치나?
④ 선택      : 안 겹치면서 + 중앙에 가까운 후보 하나
⑤ 발행      : 그 경로를 제어(pure pursuit)에 넘김
```

## 2. 준비물 — 좌표계와 변환 (여기가 제일 헷갈림)

### 문제
지도(map) 좌표계에서 도로는 **아무 방향**으로나 뻗어 있다. "왼쪽으로 1.75m" 같은 걸 계산하려면 도로가 비스듬하면 삼각함수가 지저분해진다.

### 해결
**도로가 정면(x축)을 향하는 "차 기준 좌표계(local)"로 잠깐 옮겨서** 계산하고, 다 하면 다시 지도 좌표로 되돌린다.

```
   map 좌표계(비스듬한 도로)          local 좌표계(도로가 x축)
        ╱ 도로                            ↑ y (왼쪽 +)
       ╱                        →         │
      ╱                                   └────→ x (도로 진행방향)
```

### 수식 — 두 좌표계 사이 변환

기준점 `P0 = (sx, sy)` (경로 시작점), 도로 방향각
```
θ = atan2(P1.y − P0.y,  P1.x − P0.x)      (P1 = 경로 두 번째 점)
```

**map → local** (지도 점을 차 기준으로): 먼저 P0만큼 빼서 옮기고, −θ만큼 회전
```
lx =  cosθ·(x − sx) + sinθ·(y − sy)
ly = −sinθ·(x − sx) + cosθ·(y − sy)
```

**local → map** (계산한 점을 지도로 되돌림): θ만큼 회전하고, P0만큼 더함
```
x = sx + cosθ·lx − sinθ·ly
y = sy + sinθ·lx + cosθ·ly
```

> 💡 회전행렬 `R(θ) = [[cosθ, −sinθ],[sinθ, cosθ]]`. 역회전은 `R(−θ)=Rᵀ`. 위 두 식이 정확히 그거예요.
> 원본 코드는 이걸 3×3 행렬(`trans_matrix`)과 그 역행렬(`det_trans_matrix`)로 함. 우리 코드(`toLocal`/`toWorld` 람다)는 위 식 그대로.

## 3. 후보 경로 만들기 — 3차곡선 완전 유도 ⭐

### 무엇을 원하나
local 좌표계에서, **차의 현재 옆위치**에서 시작해 **목표 offset**까지 **부드럽게** 이어지는 곡선 `y(x)`.

- 시작(x=0): 차의 현재 옆위치 `ps`, 그리고 도로와 나란히 (기울기 0)
- 끝(x=xf): 목표 옆위치 `pf`, 그리고 다시 나란히 (기울기 0)

### 왜 3차(cubic)?
조건이 **4개**(시작 위치·시작 기울기·끝 위치·끝 기울기)라, 미지수 4개짜리 다항식 = **3차**:
```
y(x) = a₃x³ + a₂x² + a₁x + a₀        (미지수 a₀,a₁,a₂,a₃ 4개)
y'(x) = 3a₃x² + 2a₂x + a₁            (기울기)
```

### 경계조건 4개
```
① y(0)  = ps      (시작 옆위치)
② y'(0) = 0       (시작 기울기 0 = 도로와 나란히)
③ y(xf) = pf      (끝 옆위치 = 목표 offset)
④ y'(xf)= 0       (끝 기울기 0 = 다시 나란히)
```

### 풀이 (직접 유도)
①에서:  `y(0) = a₀ = ps`   →   **a₀ = ps**
②에서:  `y'(0) = a₁ = 0`   →   **a₁ = 0**

남은 a₂, a₃를 ③④로:
```
③ : a₃xf³ + a₂xf² + ps = pf     →   a₃xf³ + a₂xf² = pf − ps      …(i)
④ : 3a₃xf² + 2a₂xf = 0          →   a₂ = −(3/2)·a₃·xf            …(ii)
```
(ii)를 (i)에 대입:
```
a₃xf³ + (−(3/2)a₃xf)·xf² = pf − ps
a₃xf³ − (3/2)a₃xf³ = pf − ps
−(1/2)a₃xf³ = pf − ps
```
따라서:
```
★ a₃ = −2(pf − ps) / xf³
★ a₂ =  3(pf − ps) / xf²
★ a₁ = 0
★ a₀ = ps
```

**검산** — x=xf 넣어보면:
```
y(xf) = −2(pf−ps) + 3(pf−ps) + ps = (pf−ps) + ps = pf  ✓
```

이 네 계수가 **코드의 `a[0]~a[3]`와 정확히 일치**해요. 이게 "3차곡선 계획법"의 전부입니다.

> 이 곡선을 **Hermite 3차 곡선**이라고 함 — 두 점을 "기울기까지 지정해서" 잇는 유일한 3차식.
> 6개 offset(`[-3, -1.75, -1, 1, 1.75, 3]`)마다 이 계산을 반복 → 후보 6개.

### 전방주시 거리 (얼마나 앞을 보나)
```
look = int(v_kmh × 0.2 × 2),  최소 20
```
빠를수록 멀리 봄(고속에서 급하게 틀면 위험). 경로 끝점은 `index = look×2` 지점.

## 4. 충돌 검사 — 수식

차와 장애물을 **원(circle)** 으로 근사해서, 경로 위 점이 장애물 "안전 원"에 들어오나 본다.

각 후보 경로 점 `(px,py)`와 각 장애물 `(ox,oy)`에 대해:
```
거리 d = √( (px−ox)² + (py−oy)² )

충돌 판정:  d  <  r + (차폭/2) + margin
```
- `r` = 장애물 반경 = `0.5 × max(size_x, size_y)`  ← 장애물 크기 반영
- `차폭/2` = 0.95 m (Ioniq5 폭 1.892 / 2)
- `margin` = 0.5 m (안전 여유)

즉 장애물 주위에 **`r + 0.95 + 0.5` 반경의 금지 원**을 그리고, 후보가 거기 들어가면 충돌.

```
        ╭─────╮   ← 금지 원 (r + 차폭/2 + margin)
       ( ▉장애물 )
        ╰─────╯
   후보경로가 이 원 통과 → 충돌(벌점)
```

## 5. 최적 후보 고르기 — 비용

```
lane_weight = [3, 2, 1, 1, 2, 3]     ← 기본 비용 (안쪽=중앙 가까울수록 쌈)
충돌한 후보:  weight += 100           ← 부딪히면 비싸짐
선택:  argmin(weight)                ← 제일 싼 후보
```

의미:
- 충돌 안 하는 후보들 중 **중앙(기준경로)에 제일 가까운 것** 선택 (weight 1이 제일 안쪽).
- 어떤 후보가 충돌하면 +100 되어 사실상 후보에서 탈락.

**예시**: 장애물이 정중앙에 있어 안쪽 4개(±1, ±1.75)가 다 충돌(+100), 바깥 2개(±3)만 안전이면 → 바깥 것 중 먼저 오는 −3 선택.

## 6. 언제 lattice를 돌리나 (트리거)

매번 후보 6개 그리는 건 낭비. **장애물이 경로 근처에 있을 때만** 돌리고, 없으면 기준경로 그대로 통과:
```
objectOnPath():  경로 점 중 하나라도 장애물 안전거리 안에 있으면 true
```
- true → 후보 생성·선택
- false → `/lattice_path`에 `/local_path` 그대로 발행 (평상 주행)
